  • Admin dashboard: health, disk, every queue (requests, confirms, held files, downloads, failures), approvals, users, recent activity.
  • Uptime Kuma (over Tailscale): every site and job, with alerts to your ntfy.
  • The server menu: sudo bash /root/bookstack/bookstack.sh. Deploy after checking out a new version; Operations → Update for new image versions; Operations → Self-test; Security → Authelia for the sign-in page.
  • Adding a reader: Admin dashboard → Add user. With the sign-in page on, their sign-in login is created with the same password.
  • Sign-in policy: admins always need a second factor (their Calibre-Web admin role, mirrored into the sign-in page's admins group on every Deploy); Operations → Advanced settings → lockout → AUTHELIA_READERS_2FA asks it of readers too, and AUTHELIA_PASSKEYS lets a passkey alone sign in. Deploy and Update apply the rules by themselves.
  • The start page's address: Deploy creates home. in Cloudflare only when that name is free. If another service already uses it, it is left alone and the start page is at request.…/hub instead (every link follows); move that service to another name and Deploy again to use home..
  • Promoting an admin: give them the admin role in Calibre-Web (or Users in the server menu); within 10 minutes the sign-in page asks them for a second factor too, and only then does the portal give them admin rights.
  • Readers' phone notifications use ntfy.sh unless Operations → Advanced settings → mail → READER_NTFY_URL names another server the phones can reach.
